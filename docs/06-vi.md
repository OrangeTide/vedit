# The vi keys

The vi personality, in full, for readers who do not know vi. Every key and
command the editor implements is listed here, and a key that is not listed
does nothing.

## Switching to vi

Press **F2**. The status line shows `-- NORMAL -- (F2 returns to
modeless)`. Press F2 again to return to the EDIT keys. To start in vi every time, put this in the config
file (chapter 5):

```ini
[edit]
    mode = vi
```

## The idea: modes

In the EDIT keys, every letter you type goes into the file. In vi, the
editor is usually in **normal mode**, where letters are commands: `j`
moves down, `x` deletes a character, `dd` deletes a line. To type text you
enter **insert mode** with a command such as `i`, type, then press Esc to
return to normal mode. The status line shows the mode whenever it is not
showing a message:

| Status line | Mode |
|---|---|
| `-- NORMAL --` | keys are commands |
| `-- INSERT --` | keys insert text; Esc returns to normal |
| `-- VISUAL --`, `-- VISUAL LINE --`, `-- VISUAL BLOCK --` | a selection is being made |

A `:` in normal mode opens a command line at the bottom of the screen for
the longer commands, such as `:w` to save. Enter runs the line, Esc
abandons it.

Most normal-mode commands take a **count** typed before them: `3j` moves
down three lines, `2dd` deletes two lines. Type the digits, then the
command. A count can be up to one million.

## Moving

These work in normal mode. A count repeats them.

| Key | Moves to |
|---|---|
| `h` `j` `k` `l` | left, down, up, right (the arrow keys also work) |
| Backspace, Space | left, right |
| Enter | down |
| `0`, Home | the start of the line |
| `^` | the first non-blank character of the line |
| `$`, End | the end of the line. After `$`, `j` and `k` stay at the end of each line |
| `w` `b` `e` | the next word, the previous word, the end of the word. A word is letters, digits, underscores, and non-ASCII characters, or a run of other punctuation |
| `W` `B` `E` | the same, where a word is anything between blanks |
| `gg` | the first line, or line N with a count |
| `G` | the last line, or line N with a count |
| `{` `}` | the previous or next blank line (a paragraph) |
| `(` `)` | the previous or next sentence |
| `%` | the bracket matching the one under or after the cursor: `( ) [ ] { }`. With a count, `N%` goes to N percent of the file |
| `\|` | column N |
| `H` `M` `L` | the top, middle, or bottom line of the window. A count on `H` or `L` is an offset from that edge |
| `f` *c* / `F` *c* | the next or previous character *c* on this line |
| `t` *c* / `T` *c* | just before the next *c*, or just after the previous one |
| `;` `,` | repeat the last `f F t T`, in the same or the opposite direction |
| Ctrl-D, Ctrl-U | down or up half a screen |
| Ctrl-F, Ctrl-B, PgDn, PgUp | down or up a screen |
| Ctrl-Home, Ctrl-End | the first and last line |

Up and down keep the cursor's column where they can.

## Inserting text

Each of these enters insert mode. With Auto Indent on, `o` and `O` start
the new line with the current line's indent.

| Key | Insert |
|---|---|
| `i` | before the cursor |
| `a` | after the cursor |
| `I` | at the first non-blank of the line |
| `A` | at the end of the line |
| `o` | on a new line below |
| `O` | on a new line above |
| `R` | overtype: each character typed replaces one |

In insert mode these keys are available:

| Key | Action |
|---|---|
| Esc | back to normal mode. The cursor steps back one character, as in vi |
| Enter | new line, copying the indent when auto indent is on |
| Tab | a tab, or spaces to the next stop when indenting with spaces (chapter 4) |
| Backspace, Delete | delete left, delete right |
| arrows, Home, End | move without leaving insert mode |
| Ctrl-Home, Ctrl-End | first and last line |

Other control keys are ignored in insert mode. The whole insert session,
from the command that entered it to the Esc, is one undo step. Pasting
from the terminal (bracketed paste) inserts in insert mode and is
discarded in normal mode.

## Changing text

### Operators

An operator is a command that acts on the text covered by the motion typed
after it. `dw` deletes to the next word, `d$` deletes to the end of the
line, `y}` copies to the end of the paragraph, `c3w` replaces three words.

| Operator | Action |
|---|---|
| `d` | delete, into the register |
| `c` | change: delete, then enter insert mode |
| `y` | yank: copy into the register without deleting |
| `>` `<` | indent or unindent whole lines (chapter 4 sets the width) |

Any motion from the table above can follow, including `f`, `t`, `gg`,
and a mark (`` d`a ``, `d'a`), except the scrolling keys (Ctrl-D, Ctrl-U,
Ctrl-F, Ctrl-B, PgUp, PgDn, Ctrl-Home, Ctrl-End) and the search keys
(`/ ? n N * #`), which cancel the operator. A count before the operator
and a count before the motion multiply: `2d3w` deletes six words.

Typing the operator twice acts on whole lines: `dd` deletes the line, `cc`
replaces it, `yy` copies it, `>>` and `<<` shift it. With a count, `3dd`
deletes three lines.

`cw` behaves like `ce`: it does not eat the space after the word.

### Text objects

After an operator, `i` or `a` followed by an object letter selects a
region around the cursor: `i` is the inside, `a` includes the delimiters
or the surrounding space.

| Object | Region |
|---|---|
| `iw` `aw` | the word under the cursor |
| `iW` `aW` | the blank-delimited word |
| `i(` `a(`, `i)` `a)`, `ib` `ab` | inside or around parentheses, which may span lines |
| `i{` `a{`, `i}` `a}`, `iB` `aB` | braces |
| `i[` `a[`, `i]` `a]` | square brackets |
| `i<` `a<`, `i>` `a>` | angle brackets |
| `i"` `a"`, `i'` `a'`, `` i` `` `` a` `` | a quoted string, on one line |

So `ci"` replaces the contents of the string under the cursor, `daw`
deletes a word with its trailing space, `yi{` copies the body of a block.

### Single-key edits

| Key | Action |
|---|---|
| `x`, Delete | delete the character under the cursor (N with a count) |
| `D` | delete to the end of the line |
| `C` | change to the end of the line |
| `s` | substitute: delete N characters and insert |
| `S` | substitute N whole lines |
| `r` *c* | replace the character under the cursor with *c*. `r` Enter splits the line |
| `J` | join the next line onto this one with one space (N lines with a count) |
| `~` | toggle the case of the character and move right |
| `p` `P` | put the register after or before the cursor. Whole lines go below or above the current line |

### Undo and repeat

| Key | Action |
|---|---|
| `u` | undo |
| Ctrl-R | redo |
| `.` | repeat the last change: an operator with its motion, `x`, `p`, `J`, `r`, a whole insert session, or a visual-mode operation |

## Searching

| Key | Action |
|---|---|
| `/` | search forward. The cursor follows the match as you type. Enter accepts, Esc returns to where you started |
| `?` | search backward the same way |
| `n` `N` | the next match, in the same or the opposite direction |
| `*` `#` | search for the whole word under the cursor, forward or backward |

The pattern is a regular expression (see the end of this chapter).
Searches wrap around the end of the file. `/` followed by Enter alone
repeats the last pattern. `:set ignorecase` makes searches ignore case.

## Visual mode: selecting first

Visual mode reverses the order of operator and motion: select the text
first, then type the operator.

| Key | Starts |
|---|---|
| `v` | a character-wise selection |
| `V` | a line-wise selection |
| Ctrl-V | a block: a rectangle of columns |
| `gv` | reselects the previous selection |

While selecting, the motions above move one end of the selection and the
status line shows the mode. Then:

| Key | In `v` and `V` |
|---|---|
| `d` `x` | delete |
| `y` | yank |
| `c` `s` | change |
| `p` `P` | replace the selection with the register |
| `>` `<` | shift the lines |
| `o` `O` | move the cursor to the other end |
| `iw` `a(` and the other objects | select that object instead |
| `v` `V` Ctrl-V | switch to that kind of selection, or leave when it is the current kind |
| Esc | leave without doing anything |

In a block selection (Ctrl-V):

| Key | Action |
|---|---|
| `d` `x` | delete the rectangle from every row |
| `y` | yank the rectangle. `p` later pastes it back as a rectangle |
| `I` | insert at the left edge of every row: type the text on the top row, and Esc copies it down. Rows too short to reach the column are skipped |
| `A` | append past the right edge of every row, padding short rows |
| `>` `<` | shift the lines |
| `o` `O` | move to the diagonally opposite corner |

Block columns are counted in bytes, so a block over tabs or multibyte text
does not line up exactly.

## Registers

Deleted and yanked text goes into a register, and `p` puts it back. With
no register named, the unnamed register is used, which is also what
Ctrl-C and Ctrl-V use in the EDIT keys. To use a named register, type
`"` and a letter before the command:

| Form | Action |
|---|---|
| `"ayy` | yank the line into register `a` |
| `"ap` | put register `a` |
| `"Ayy` | append to register `a` |

Registers are `a` to `z`. There are no numbered registers and no
clipboard registers; the whole-line and character-wise distinction is
kept, so a yanked line pastes as a line.

## Macros

A macro records the keys you type into a register and plays them back.

| Key | Action |
|---|---|
| `qa` | start recording into register `a`. `qA` appends |
| `q` | stop recording |
| `@a` | play register `a` |
| `@@` | play the last macro again |
| `5@a` | play it five times |

A macro records raw keystrokes, so it can also be built with `"ayy` on a
line of commands. A `:` command, a `/` search, and the function keys do
not run from inside a macro: the key is dropped and what follows it is
read as normal-mode keys.

## Marks and the jump list

A mark remembers a position in the buffer.

| Key | Action |
|---|---|
| `ma` | set mark `a` (any letter `a` to `z`) |
| `` `a `` | jump to the exact position of mark `a` |
| `'a` | jump to the first non-blank of its line |
| `` g`a `` `g'a` | the same, without recording a jump |
| `:marks` | list the marks and pick one |
| `:delmarks a b` | clear marks `a` and `b`; `:delmarks!` clears `a` to `z` |

Some marks are set for you:

| Mark | Position |
|---|---|
| `` ` `` or `'` | where you were before the last jump, so ``` `` ``` toggles between two places |
| `.` | the last change |
| `^` | where insert mode last ended |
| `<` `>` | the start and end of the last visual selection |
| `[` `]` | the start and end of the last change or yank |

A mark stays on its line number when lines above it are inserted or
deleted.

A **jump** is a long move: `G`, `gg`, `H M L`, `%`, `{ }`, `( )`, a
`/` or `?` search, `n`, `N`, or a mark jump. The editor keeps a list of them, across files:

| Key | Action |
|---|---|
| Ctrl-O | go back to the previous position in the jump list |
| Ctrl-I, Tab | go forward again |
| `:jumps` | list the jump list and pick an entry |

## Saving and quitting

| Key | Action |
|---|---|
| `ZZ` | save if modified, then quit |
| `ZQ` | quit, discarding changes |
| `:w` | save (write). `:w!` writes a read-only buffer |
| `:w name` | save under a new name, which becomes the buffer's name |
| `:q` | quit. Refuses when the current buffer has unsaved changes |
| `:q!` | quit, discarding changes |
| `:wq`, `:x` | save, then quit |
| `:qa`, `:wqa` | the same as `:q` and `:wq` |
| `:cq` | quit with a failure exit status, which tells `git commit` to abort |

Quitting ends the whole editor. Only the current buffer is checked for
unsaved changes, and only the current buffer is written by `:wq` and
`:wqa`, so save the other buffers first. The crash-recovery journal
(chapter 3) keeps their edits in any case.

In the vi keys, save with `:w` and quit with `:q`. The File menu works in
both personalities.

## Files and buffers

| Command | Action |
|---|---|
| `:e name` | open a file (edit). A file that is already open is switched to |
| `:e` | reload the current file from disk, discarding unsaved changes |
| `:enew` | a new empty buffer |
| `:r name` | read a file in below the cursor line |
| `:ls`, `:buffers`, `:files` | show the buffer list on the status line |
| `:b N` | switch to buffer N |
| `:bn`, `:bp` | next and previous buffer |
| `:bd`, `:bd!` | close the buffer, or close it discarding changes |

## The `:` command line

Command names may be abbreviated to any prefix down to their usual short
form, so `:w` is `:write`, `:bn` is `:bnext`, and `:sor` is `:sort`. The
aliases `:xit`, `:exit`, `:xall`, `:quitall`, `:bprevious`, `:bNext`,
`:files`, and `:buffers` work too.

### Ranges

Many commands take a range of lines before the name. A range is one or two
addresses:

| Address | Lines |
|---|---|
| `N` | line N |
| `.` | the current line |
| `$` | the last line |
| `%` | every line (the same as `1,$`) |
| `'a` | the line of mark `a` |
| `+N`, `-N` | relative to the current line, or to the address before it |
| `A,B` | from A to B |
| `A;B` | from A to B, where B is counted from A |

So `:10,20d` deletes lines 10 to 20 and `:%s/x/y/g` substitutes in the
whole file. A range with no command after it moves to its last line. A
pattern cannot be used as an address, and `'<,'>` for the visual
selection is not supported: use `V` and the operator keys instead. The
commands that take a range are `:N`, `:d`, `:y`, `:>`, `:<`, `:r`, `:s`,
`:g`, `:v`, and `:sort`; every other command ignores one.

### Editing commands

| Command | Action |
|---|---|
| `:N` | go to line N |
| `:[range]d` | delete the lines, into the register |
| `:[range]y` | yank the lines |
| `:[range]>`, `:[range]<` | shift the lines one level |
| `:[range]r name` | read a file in below the last line of the range |
| `:[range]s/old/new/` | substitute the first `old` on each line with `new`. Add `g` to replace every occurrence. The range defaults to the current line |
| `:[range]g/pat/cmd` | run `cmd` on every line matching `pat`, where `cmd` is `d`, `y`, `s/a/b/`, `>` or `<`. The range defaults to the whole file |
| `:[range]v/pat/cmd`, `:g!/pat/cmd` | the same on every line that does not match |
| `:[range]sort` | sort the lines, the whole buffer by default. Options after it: `n` numeric, `i` ignore case, `r` reverse, a number N to sort by the text from byte N. `:sort!` also reverses |
| `:retab` | convert the indentation of the selection, or the whole buffer, between tabs and spaces, following the indent setting |
| `:format` | run the formatter for the file type (chapter 7) |
| `:date` | insert today's date. `:date 2026-12-25` inserts that day |
| `:tabstops 5 9 17` | set a ruler of tab stops for the buffer (chapter 4). `:tabstops` alone shows it, `:tabstops off` clears it |
| `:!cmd` | run a shell command in a terminal buffer (chapter 7) |

In `:s`, any punctuation character can replace `/` as the delimiter, and
the pattern cannot contain the delimiter. An empty
pattern reuses the last search. Flags other than `g` are ignored; case
sensitivity follows `:set ignorecase`. The replacement understands `&` for
the whole match, `\1` to `\9` for groups, and `\U \L \u \l \E` to change
case. The whole substitution is one undo step.

### Options: `:set`

`:set name` turns an option on, `:set noname` off, and `:set name!` flips
it. The short forms work with `no` as well; with `!` they work for `nu`,
`ai`, and `et` only, so write `:set ignorecase!` in full. Options with a
value are `:set name=value`. One option per command.

| Option | Short | Controls |
|---|---|---|
| `number` | `nu` | the line-number gutter |
| `wrap` | | word wrap |
| `list` | | the guide glyph on hard tabs |
| `mouse` | | mouse reporting |
| `autoindent` | `ai` | new lines copy the previous indent |
| `expandtab` | `et` | indent with spaces rather than tabs |
| `ignorecase` | `ic` | searches ignore case |
| `swapfile` | `swf` | the crash-recovery journal |
| `backup` | `bk` | keep the previous version as `name~` |
| `formatonsave` | `fos` | run the formatter before each save |
| `tabstop=N` | `ts` | the width of a tab |
| `shiftwidth=N` | `sw` | how far `>>` shifts; 0 means one tab stop |
| `fileformat=unix\|dos\|nul` | `ff` | the line endings written on save |
| `dateformat=PATTERN` | `df` | the `strftime` pattern `:date` uses |
| `paneheight=N` | `ph` | the height of the pane (chapter 7); 0 means a third |

Chapter 4 describes what each view setting does.

## Regular expressions

Searches, `:s`, and `:g` use the same pattern language as the EDIT
personality's find and replace. It is POSIX extended regular expressions
with the usual extras:

| Pattern | Matches |
|---|---|
| `.` | any character |
| `*` `+` `?` | zero or more, one or more, zero or one of the preceding item. `*?` `+?` `??` match as little as possible |
| `{n,m}` | between n and m repetitions |
| `[abc]` `[a-z]` `[^x]` | a set, a range, a negated set; `[[:alpha:]]` and the other POSIX classes |
| `\d` `\w` `\s` | a digit, a word character, a blank |
| `^` `$` | the start and end of the line |
| `\b` `\B` `\<` `\>` | a word boundary, a non-boundary, the start and end of a word |
| `(...)` `(?:...)` | a group that is captured, or not |
| `a|b` | alternatives; `\|` matches a literal bar |
| `\1` | what group 1 matched |

A pattern matches within one line. The engine is byte oriented.

## What is not implemented

For readers who know vi or vim, these are absent.

- Keys: `X`, `Y`, `U`, `K`, `Q`, `&`, `+`, `-`, `_`, `!`, `=`.
- The `z` scrolling commands (`zz`, `zt`, `zb`), Ctrl-E and Ctrl-Y, and
  Ctrl-A and Ctrl-X on numbers.
- `g` commands other than `gg`, `gv`, `gf`, `` g` `` and `g'`: no `gu`,
  `gU`, `g~`, `gJ`, `gi`, `ge`, `gj`, `gk`, `g*`, `gd`, `gq`.
- The `[` and `]` motions.
- Counts on `i a I A o O`, on `p`, on `.`, on `u`, and on visual-mode
  operators.
- A search as an operator target (`d/pat`, `dn`).
- The sentence, paragraph, and tag text objects (`is`, `ip`, `it`).
- Uppercase (file) marks. Marks do not follow edits.
- Numbered, clipboard, and other special registers.
- Insert-mode Ctrl-W, Ctrl-U, Ctrl-R, Ctrl-T, Ctrl-D, Ctrl-O, Ctrl-N,
  Ctrl-P, Ctrl-V.
- In visual mode: `~`, `u`, `U`, `J`, `r`, `D`, `C`, `S`, and `I` and `A`
  outside block mode; in block mode `c`, `s`, `r`, `p`, `P`, `i`, `a`,
  `~`, and `J`.
- Ex: `'<,'>` and pattern addresses, `:m`, `:t`, `:j`, `:norm`, `:map`,
  `:ab`, `:noh`, and flags on `:s` other than `g`.
